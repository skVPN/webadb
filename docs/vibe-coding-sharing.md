## 分：四个阶段怎么做的（6 分钟）

### 阶段一：核心功能搭建（对话 1-10）

| 我说的 | AI 做的 |
|--------|---------|
| "写一个基于 WebADB 协议的 HTML" | 调研技术方案，创建 4 个 JS 模块 + HTML |
| "部署到 Cloudflare" | 配置 wrangler.toml，一键部署 |
| "连接不上" | 通过浏览器 MCP 远程调试，定位 ADB server 冲突 |
| "截屏失败" | 分析 exec vs shell 协议差异，加双模式回退 |
| "下拉不支持" | 加 mousedown/mousemove/mouseup 拖拽滑动 |

**踩坑：** ADB 认证的 RSA 签名，Web Crypto API 会自动做 SHA-1 哈希导致双重哈希。AI 查了 Android 源码，手动用 BigInt 实现了 PKCS#1 v1.5 prehashed 签名。这种底层协议问题，AI 比人查资料快 10 倍。

### 阶段二：产品化包装（对话 10-25）

| 我说的 | AI 做的 |
|--------|---------|
| "加 Google AdSense" | 一行代码搞定 |
| "生成技术教程" | 基于源码生成 4 模块交互式 HTML 教程 |
| "加隐私政策和免责声明" | 所有页面加页脚 + 弹窗，符合 AdSense 审核 |
| "上传 GitHub + 写 README" | git init → commit → push + 完整 README |

**关键动作：** 每做完一个功能就 deploy + git push，保持可交付状态。

### 阶段三：AI 营销功能（对话 25-40）

| 我说的 | AI 做的 |
|--------|---------|
| "接入 LLM 生成营销日历" | 创建 /ai 配置页 + 对话生成 + 日历 UI |
| "用 AutoGLM 控制手机执行" | 截屏→AI分析→ADB操作 的执行循环 |
| "加飞书日报通知" | LLM 生成日报摘要 → Webhook 推送 |
| "多设备数据隔离" | localStorage key 按设备 ID 分区 |

**架构决策：** 所有数据存浏览器 localStorage，不上传服务器。模型配置全局共享，日历/日志按设备隔离。这些都是我口头描述，AI 自动设计存储结构。

### 阶段四：Landing Page + 运营（对话 40-55）

| 我说的 | AI 做的 |
|--------|---------|
| 贴了一段别人对页面的差评 | 用 ui-ux-pro-max 生成设计系统，全面重构 Landing Page |
| "连接后跳转新页面" | 首页/控制页分离，WebUSB getDevices 自动重连 |
| "加访问统计" | 创建 D1 数据库 + Worker API + /monitor 看板 |
| "生成发布文案" | 300 字发布内容 + 亮点列表 |

**最有意思的：** 我把别人的差评原文贴给 AI，它逐条分析并全部修复 — Hero + Features + Steps + Trust + FAQ + CTA，从 3/10 的设计分直接拉满。

## 总：5 个关键技巧 + 适用场景（2.5 分钟）

### 技巧

1. **描述问题，不描述方案** — "截屏失败了，这是日志截图" 比 "在 receive 函数加 try-catch" 好 10 倍
2. **给 AI 看截图** — 浏览器 MCP 让 AI 直接操作你的浏览器调试，比文字描述高效
3. **迭代式开发** — 每次一个功能点，验证通过再下一个，不要一次提 5 个需求
4. **善用 Skills** — ui-ux-pro-max 避免程序员审美，free-tool-strategy 做 SEO 优化
5. **让 AI 做运维** — deploy、git push、D1 建表、DNS 配置，全让 AI 执行

### 适合场景

✅ 内部工具快速原型 / 个人项目 / 技术 POC / 落地页

❌ 核心业务系统 / 高并发后端 / 大型代码库维护

### 想试试？

从一个小工具开始："帮我写一个 JSON 格式化工具"，先跑通流程再做复杂项目。
